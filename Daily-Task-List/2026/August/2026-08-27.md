## 记录
重构 PPT 渲染产线：SVG 手写 → pptx 模板换字

Context

现在是怎么跑的

三阶段里前两阶段（slides_plan / slides_content）已经很干净：ChatAgent +
camel 结构化输出，产出 DeckPlan 与 list[SlideContent]，再由
assemble_source_md() 拼成 source.md（一个 ##  一页）。

第三阶段 slides_render 是另一套东西：

source.md → 常驻 opencode 容器（HTTP）→ 模型读 SVG 参考版式 → 逐页手写 SVG
         → svg_quality_checker 逐页纠错循环 → finalize_svg → svg_to_pptx → exports/*.pptx

代价与风险：

- 30~60 分钟一份 PPT，idle_timeout 配到 3600 秒；max_rounds 催轮次。
- 依赖一个仓库外的 ocppt-opencode:latest 镜像，/app/skill 与 /app/template
  由 Dockerfile COPY 钉死。本仓库里既没有 skill 也没有模板，渲染行为对这个
  仓库完全不可见、不可版本化。（构建定义在 steins-devops@shou_confer_middle）
- components/opencode/ 五个文件近 1500 行，全部是为了「隔着 HTTP 驱动一个
  agent 在容器里干活」——建会话、传文件、跑 shell、轮询、判完成、取产物。
  模型会谎报完成，所以结束判据只能是去容器里列目录。
- 提示词 prompt.py 67 行里大半是在给模型补歧义的坑（页数锁定、图片必须同时登记
  两处、逐页跑质检器不要预推算……），注释本身记录了「靠模型的余量兜我们的歧义，
  不是设计，是运气」。
- 项目内还有两套模型调用栈（camel ChatAgent / opencode HTTP），一直挂在待办上。

换成什么

参考 draft/repositories/GordenPPTSkill。它的做法本质是：不生成版式，只在一份
现成的 .pptx 里选页 + 按 run 换字。模型的产物从「N 份手写 SVG」缩成「一份
edits.json」，排版/配色/字号因为根本没被碰过而天然一致。

它的脚本与元数据结构是 MIT 且明确允许商用（NOTICE.md），只有 21 套模板视觉
素材受限——所以我们只借机制，模板自制。

目标形态：

SlideContent[] → 版式映射选页（确定性）→ 逐页 ChatAgent 结构化输出槽位文本
              → 容量 lint（超框重写，不截断）→ 进程内 python-pptx 换字 → pptx bytes

一次任务从 30~60 分钟降到分钟级，无容器、无镜像依赖，模型调用栈收敛成一套。

已决定的三个前提

1. 彻底去掉 opencode，Stage3 改为 camel ChatAgent + 进程内 python-pptx。
2. 自制海洋主题模板，不使用 Gorden 的 21 套内置模板。
3. 保住「一页对一页」的页数契约，移植时修掉 Gorden 复页会被静默吞掉的缺陷。

分支

从 dev 切新分支（dev 是当前 HEAD 的祖先，切出去干净）。当前分支
bugfix/steins-algorithm-critical 上那 3 个 opencode 相关提交不带过去——反正
opencode 整个要删。

分支名需过 CI 的分支名校验，建议 refactor/ppt-render-pptx-template。

Step 2 — 生成 detail.json（脚本，可重跑）

新增一次性工具 steins-algorithm/tools/build_template_detail.py（不进运行时依赖）：

1. 遍历 template.pptx 每页每个 shape（递归 group，参考
   GordenPPTSkill/scripts/build_pptx.py:find_shape），抓出所有含
   {{TOKEN}} 的 run，写成 slot：
   slot_id = TOKEN，address = {shape_id, paragraph, run}，
   current_text = "{{TOKEN}}"。
2. 从 token 名派生 role / editable / guidance
   （PAGE_NUM / CHAPTER_NUM → editable: false；*_TITLE → 标题；
   *_TEXT_L1/L2 → 正文行）。
3. 容量字段直接移植 GordenPPTSkill/scripts/compute_capacity.py 的算法：
   box_cm / font_size_pt / chars_per_line / max_lines / max_chars
   / wrap / autofit，以及根级 type_scale + 每槽 level。
   常量照抄：H_MARGIN_CM=0.25、V_MARGIN_CM=0.08、LINE_HEIGHT=1.0、
   TOLERANCE=1.2；视觉宽度 CJK=1.0 / 空格=0.35 / ASCII=0.5 / 其他=0.8。
4. 页级元数据（role / layout / use_for）从 template.toml 的
   [references] 映射直接得到——版式 key 就是 SlideLayout 的值。

输出 ppt_templates/marine/detail.json，提交进仓库。模板改了就重跑这个脚本。

新增模型 steins_agent/models/render_edits.py：

class SlotFill(BaseModel):
    slot_id: str
    new_text: str

class PageFill(BaseModel):          # 一页一次结构化输出
    fills: list[SlotFill]

为什么是逐页而不是整份 edits.json：Gorden 让模型一口气写完整份，密集模板
一页 40+ 个字符串、整份数百条，且它的 detail.json 动辄 1MB——上下文直接炸。
逐页则每次只喂该页的槽位表（十几条），可并发、可单页重试，
config/steins-algo-agent-zh-v3.yaml 里预留的 page_concurrency: 6 正是这个形状。

Step 5 — 复页：修掉 Gorden 的静默吞页

GordenPPTSkill/scripts/build_pptx.py:prune_slides 的做法是把
sldIdLst 的元素摘下来按新顺序 append 回去。同一个索引出现两次时，lxml 的
append 是「移动」不是「复制」，第二次会把元素从原位挪走——结果是少一页，
且不报错。 已实测确认。

我们的 builder.py 必须支持复页：对重复选中的页做 slide part 深拷贝
（复制 slide.element 以及它的 rels——图片/图表关系要跟着复制，否则新页丢图），
再插进 sldIdLst。

另外 Gorden 那份 prune 只改 sldIdLst，被丢弃的 slide part 仍留在包里（体积
虚胖但无害）；我们顺手把孤儿 part 一起删掉。

RenderRequest.expected_pages（schemas/request/render.py）已有的页数核对保留，
判据从「数 zip 里的 slideN.xml」换成「数构建后的 slides」。

Step 6 — 容量 lint：提示，不阻断

移植 Gorden 的策略，原样保留它最重要的那条产品判断：

▎ 绝对禁止为了凑数而砍掉后半句、在结尾加 ... / … / 等等——
▎ 被省略号截断的半句话，比轻微超框难看得多，是最差的结果。

实现：
- 超框 → 把超框槽位连同「用更精炼的措辞重写，不要截断、不要改字号」回喂给模型，
  最多 max_fix_rounds 轮（v3 config 里已预留 = 3）。
- 轮次用尽仍超框 → 照样写进去并放行，只打 warning。
- 结尾是 ... / … / 等等 → 直接判为需要重写，这比超框更该拦。
- autofit 的框、capacity_unknown 的框跳过检查。

这条也呼应仓库里已有的一条经验：格式指路交给上游文档、取值我们写死；
不要复述格式造出两份真相。槽位的容量数字只在 detail.json 里存在一份。

需要留意的风险

- Step 1 是唯一的不确定项。svg_to_pptx 能否把 13 份 SVG 转成 token 不被
  拆 run 的干净 pptx，要跑过才知道。转出来若 token 被拆进多个 run，
  detail.json 抽取会失败——那就走路线 B 手工排版。其余所有步骤不依赖这个选择，
  因为抽取脚本只认 {{TOKEN}}，不关心 pptx 是谁产的。
- 版式表达力从此被模板库存框住。SVG 手写时模型能临场调整版式，
  pptx 换字不能——一页有几个要点位就是几个。这正是
  LAYOUT_CAPACITY 要按模板重算的原因，也意味着 Stage1/2 的 density 档
  在超出版式容量时会被夹住（points_budget() 已有这个夹取逻辑，行为不变）。
- 图表/装饰形状改不了。进度条弧长、环形图占比这类是固定形状，改数字文字
  不会改图形。首版模板里不要放这类元素，或明确标成 editable: false。
