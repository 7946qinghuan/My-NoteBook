### 重建步骤（你自己执行）

当前状态：worker 已停、四个 ocppt 容器已删、两个镜像都在、构建资产已暂存。

#### 第 1 步：确认你在仓库根
```bash
cd /mnt/steins/zhihao/SHOU_Project/shou-confer-platform
pwd
```
必须是仓库根。 Dockerfile 里所有 COPY 都写的是 resources/docker/opencode/xxx，构建上下文不是仓库根就全部找不到。

#### 第 2 步：拉资产
```bash
resources/docker/opencode/fetch-assets.sh
```

该看到（新加的那段）：
```
[fetch-assets] 导出 skill @ 717379177 7a8 → .../skill
[fetch-assets] 本次用料：
[fetch-assets]   skill      717379177 7a8 ← https://github.com/comet-7x/ppt-master.git
[fetch-assets]   opencode   0cbfb6de55aa… ← 已暂存的 .../opencode-bin
[fetch-assets] 完成。接着构建：
```

关键是最后那行 ← 已暂存的。如果它显示 ← /home/zhihao/.opencode/bin/opencode，立刻停下——那份是 1.18.14，校验和对不上，不该被选中。

▎ 这一步会 rm -rf skill/ 再重新导出。skill 是从缓存里按提交号导的，缓存已有 593M blob，不需要联网。

#### 第 3 步：构建
```bash
docker build -f resources/docker/Dockerfile.opencode -t ocppt-opencode:latest .
```

三个强校验会在构建中依次跑，任何一个不过就直接失败（这是有意的）：

| 层                    | 校验                                                    |
| -------------------- | ----------------------------------------------------- |
| COPY opencode-bin 之后 | sha256sum -c + opencode --version \| grep -qx 1.17.18 |
| COPY skill 之后        |  .skill-ref 比对 ARG SKILL_REF                          |

pip 那两层（skill-req.txt 和 cairosvg）走清华源，是最可能因网络失败的地方。

#### 第 4 步：验收 —— 镜像与仓库一致
```bash
diff <(docker run --rm --entrypoint sh ocppt-opencode:latest \
        -c 'cat ~/.config/opencode/opencode.jsonc') \
     resources/docker/opencode/opencode.jsonc \
  && echo "✅ 一致" || echo "❌ 对不上"
```

这是本次重建的核心验收点。 现在跑是 ❌（老镜像缺整个 permission 段），重建后必须变 ✅。

#### 第 5 步：起 worker
```bash
cd steins-algorithm
CONFIG_SOURCE=local uv run python -m steins_render.main
```

该看到：
```bash
INFO:     Uvicorn running on http://0.0.0.0:8910
```

此时容器还不存在——常驻容器是第一次渲染时才起的。

第 6 步：另开一个终端，确认健康

curl -s http://127.0.0.1:8910/health | python3 -m json.tool

image_present 和 workspace_present 都该是 true。

---
第 5 步之后容器会自动重建，不用你手工 docker run：第一次渲染时 adopt_running() 发现容器不在 → start() → _rm_existing() → 用新镜像起 ocppt-shared。
