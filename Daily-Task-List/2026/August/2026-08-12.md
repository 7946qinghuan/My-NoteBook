### 设计思路

三条决定性的设计：
1. 决定一：失败是结果，不是异常
调用方等了十几分钟，需要的是"为什么没成"，不是一个 ConnectionError。
```
推论（后面会一一撞见）：RenderResult 有 ok / error 字段；render() 里有个 except Exception 带 noqa: BLE001；排队超时返回的是失败结果而不是抛异常；/render 端点失败也回 HTTP 200。推论（后面会一一撞见）：RenderResult 有 ok / error 字段；render() 里有个 except Exception 带 noqa: BLE001；排队超时返回的是失败结果而不是抛异常；/render 端点失败也回 HTTP 200。
```

2. 决定二：判据看磁盘，不看模型
模型会说"我做完了"。只有 exports/ 下真出现 .pptx 才算数。
```
推论：run_until(done=...) 收一个谓词而不是解析模型回复；find_latest_pptx() 是"渲染是否成功"的唯一判据；它被反复调用（所以有 stat 竞态，我们昨天修了）；产物 0 字节也要拦（文件在≠产物有效）。
```

3. 决定三：容器常驻共用，不是一任务一个
ocppt-shared 一直活着，每个任务在里面开一个会话，各绑 /workspace/<任务名>。
```
推论（这条最重要，也最容易出事）：
- 容器不再是任务之间的边界 → 隔离全靠按会话下发的两条 permission 规则
- 容器活着但配置可能过期 → 于是有 is_running() 里那三重比对（镜像 ID / 挂载源 / 环境变量）
- 会话必须绑对目录，而绑错不会报错 → 于是 create_session 有三道校验
- 任务名必须唯一 → 昨天加的同名并发防护
- 那个无鉴权的 opencode 服务从"活十几分钟"变成"一直活着" → 于是 --hostname 要收紧到 127.0.0.1
```


###  重建镜像的步骤

```bash
cd /mnt/steins/zhihao/SHOU_Project/shou-confer-platform
```

#### ① 停掉常驻容器（它锁着旧镜像，不删的话新镜像建完也不会被用）
```bash
docker rm -f ocppt-shared
```

#### ② 停掉本机在跑的 worker（8910 那个进程），否则它会在你重建期间又把容器拉起来
先看 PID：`ps -ef | grep steins_opencode.main`

#### ③ 删旧镜像
```bash
docker rmi ocppt-opencode:latest
```

#### ④ 资产先只读检查（不需要重拉，skill 和二进制都还在上下文里）
```bash
resources/docker/opencode/fetch-assets.sh --check
```

#### ⑤ 重建。⚠️ 末尾的 `.` 不能少，构建上下文必须是仓库根
```bash
docker build -f resources/docker/Dockerfile.opencode -t ocppt-opencode:latest .
```

#### ⑥ 验收 —— 这一步是重点，它同时验了配置生成和新的 hostname 收紧
```bash
resources/docker/opencode/check-protocol.sh
```

#### ⑥ 该看到：
```
① GET /config —— 容器里那份配置是否被正确加载
  ✅ provider / 模型 / permission 都在回显里
     · provider: probe-provider          ← 关键：是 probe-provider，不是 steins-middleware
② POST /session?directory=/workspace/probe
  ✅ 回显 directory=/workspace/probe
退出码 0
```

如果 ① 还是显示 steins-middleware 加真实端点，说明镜像没换成（多半是 ③ 没删干净，或 d 是现在的状态。

⚠️ 重建后 ocppt-shared 会由 worker 在下次渲染时自动拉起，不用手动起。

学习规则：
- 你代指用户本身
- 我代指AI

1. 我敲命令,你不敲。 你从现在起不再执行任何操作命令。
2. 每一步先说预期,再敲。 这是硬性的——我不说预期,你就不看结果。「预期」不用长,一句话:我觉得会看到 X。
3. 卡住了说"卡住了",提示分三档,指定我要哪一档:
  - ① 方向 —— 「这个问题出在配置层,不在容器层」
  - ② 位置 —— 「去看 xxx.py 的 yyy 函数」
  - ③ 答案 —— 直接说
默认给 ①。多要一档要自己开口——这个摩擦是故意的。
4. 不许查笔记和文档(draft/ 下那 8 份、docs/guides/)。
可以查:--help、报错信息、日志、以及源码本身。
▎ 这条界线是有理由的:真排错时你手边就是这些。被禁的只是「已经嚼碎的答案」。
