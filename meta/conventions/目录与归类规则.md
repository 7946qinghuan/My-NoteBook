# 目录与归类规则

决定"一篇新笔记该放哪"的唯一依据。判断顺序从上往下，命中即停。

## 顶层区域

| 目录 | 放什么 | 判断标准 |
|---|---|---|
| `Knowledge_Base/` | 可复用的主题参考笔记 | 这篇笔记以后还会被检索、引用、复制粘贴用，**内容与写作时间无关** |
| `Daily-Task-List/` | 每日笔记，一天一个文件 | 记录"今天做了什么/要做什么"，时间线性质 |
| `Plans/` | 个人成长/学习计划 | 跨月甚至跨年有效，不属于某一天 |
| `Inbox/` | 未归类草稿、临时速记 | 还没想好放哪。**定期应该被清空** |
| `meta/` | 模板与本仓库自身的规则 | 关于 vault 怎么用，不是知识内容本身 |
| `images/` | 所有图片附件 | 全部平铺，不按笔记建子目录 |

## Knowledge_Base 的 7 个域

**顶层固定 7 个域，不新增第 8 个。最多两层子目录。**

| 域 | 涵盖范围 |
|---|---|
| `AI-Engineering/` | Agent、RAG、Prompt-Engineering、VectorDB |
| `Dev/` | Python、C、Web、Backend、Database |
| `Toolchain/` | Linux、Mac、Git、VSCode、Terminal、Network、Anaconda |
| `Embedded-System/` | STM32、OpenMV、Raspberry-Pie、Arduino、Jetson、MaixCam、嘉立创 |
| `Projects/` | 按项目组织的设计文档与过程记录（如 `WTO-IOTC/`） |
| `Workplace/` | Management、Reflections、Writing-Standards |
| `Productivity/` | Obsidian、Office |

新主题优先放进已有域的子目录。只有当内容完全不属于这 7 个域时，才考虑新开顶层域——这应该很少发生。

## 为什么是 7 个域

重构前有 28 个顶层目录装 127 篇笔记，其中 **13 个目录只有 1 篇**（Git、Web、Tmux、Storge、PicGo、Webhooks…），而且混着四种不同性质的分类维度：编程语言、工具环境、AI 领域知识、和一个项目。这种结构下每次新建笔记都要重新纠结分类，实际效果等于没分类。

收敛成 7 个域之后，"这篇放哪"通常一眼就能定。

## 归类前必须查重

新建笔记前先用 `vault-search` skill 或 grep 搜一下关键词，确认相关主题下有没有类似笔记。

**教训**：曾经有 4 份简历评分表散落在不同月份目录里（文件名还都叫"未命名 1/2/3"），事后才合并到 `Knowledge_Base/Workplace/Management/招聘评分表/`。宁可花 10 秒搜一下，也不要重复造轮子。

如果发现已有高度重叠的笔记，优先**合并/追加**到那一篇，而不是新建重复的。
