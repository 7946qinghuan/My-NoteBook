# Vault Search

这是一个轻量、零基础设施的检索方案：不建向量索引，靠 grep 定位 + 读取相关笔记 + LLM 综合作答。vault 规模（几百篇笔记）下这个方式足够快，也不需要额外维护一套 embedding 服务。

## 步骤

1. **拆解问题**，提取关键词（包括同义词/相关术语，比如问题提到"代理"，也要想到"proxy"、"V2Ray"、"Clash"）。

2. **定位候选笔记**：
   - 优先在 `Knowledge_Base/` 下按目录名和文件名 grep 关键词。也可以先看 `Knowledge_Base/Knowledge-Base-MOC.md` 和各域的 `<域>-MOC.md` 索引页，快速定位问题属于哪个域。
   - 找到一篇相关笔记后，看它末尾的 `## 相关笔记` 小节——那里的双链通常直接指向同一类问题的其他笔记，比再 grep 一轮更准。
   - 也搜 `Daily-Task-List/`（任务清单里可能记录了当时做过的事）和 `Plans/`。
   - 用 `grep -ril` 找文件名/内容匹配，必要时用文件名模式再补一轮（中文笔记标题本身就是很强的分类信号）。

3. **读取候选笔记的正文**（不要只看文件名就下结论），排除掉标题看起来相关但内容不对口的。

4. **综合作答**：
   - 直接回答问题，不要只是罗列"你有这些笔记"。
   - 每个关键结论标注来源笔记路径（相对 vault 根目录），方便用户在 Obsidian 里跳转。
   - 如果找到多篇笔记内容有出入或版本演进（比如同一个 prompt 有 V1/V2/V3），指出这一点，并说明采用的是哪一版。
   - 如果没找到相关笔记，明确说"vault 里没有找到"，不要编造内容；可以主动建议用 `note-capture` 把答案记下来。

## 不要做的事

- 不要引入需要额外服务/依赖的检索方案（embedding、向量库等）——这个仓库刻意选择了零基础设施的方案。
- 不要把没读过正文、只匹配到文件名的笔记当作答案来源。
